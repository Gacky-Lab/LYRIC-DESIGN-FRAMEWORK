# 検証プロトコル：狙いと実際の受け取りを分ける

## 1. 検証対象を明示

- **文章のみの評価:** 歌詞全文／サビだけ／題名など、提示範囲を固定。
- **歌詞だけの効果:** 同じメロディー・歌唱モデル・演奏・速度・音量で歌詞だけ変更する。
- **音楽作品の総合比較:** Sunoで別生成した音源は、歌詞・旋律・歌声・編曲が複合して変化しうるので「歌詞単独A/B」と表示しない。

## 2. 試験票（例）

**聴く前:** 対象曲のジャンル経験、提示順序、音量条件、同意取得。  
**聴いた直後:** 自分事化・共感、理解度、再聴意向、印象に残った一行（自由記述）、既視感。  
**翌日:** 覚えている一行や印象（回答した人だけを分母とする）。  
**任意:** 歌詞を表示した条件・表示しない条件も別試験に。

## 3. 記録すべきメタデータ

`experiment_id`、`song_id`、`lyric_version`、`audio_version`、`condition`、`randomization`、`listening_device`、`presented_duration`、`consent`、`response_time` 等。

- 条件を揃えた証拠がない場合、結果を**探索的な比較**として扱う。
- 複数要素が変われば**複合A/B**と明記。
- 小規模な差・恣意的な点数境界を有意差と呼ばない。
- 数値は必ず実データがある場合のみ記入し、観測なしを0件・0点の成果として扱わない。

## 4. 変更管理

一つの改稿で直す主因を一つ選び、`version_id` とその根拠を記録する。実際の結果から主因仮説が反証されたときは、基盤自体も改訂する。

## 5. 倫理・プライバシー

試聴者の回答は本人同意の範囲で利用。氏名・連絡先・アカウントID・音声・生データを公開リポジトリにアップロードしない。個別の回答を引用する場合は必要な権利と同意を確認する。

## 6. 最小限の事前計画（将来の実測用）

1. **主目的を1つ決める：** 例えば「翌日、印象的な1行を自力で再生できる回答者の割合」。共感や再聴意向は副次指標として区別する。
2. **比較方法を明記：** 同じ歌詞表示条件、同じ旋律・声・編曲で、提示順をランダム化する。条件を固定できない場合は複合比較と呼ぶ。
3. **母数を記録：** 招待・同意・即時回答・翌日回答の人数を別々に集計し、翌日回答者の偏りや欠測を報告する。
4. **評価者の独立性：** 作者による編集採点と、聴取者の回答を混同しない。採点者間の違いがあれば記録する。
5. **解釈の境界：** 少人数の探索的な試験は探索的な結果として報告し、統計的な有意差や一般化を主張しない。
6. **公開条件：** 匿名化・同意確認のうえ、個人を再識別しうる生データは公開しない。

**現時点の検証ステータスは未実施。** [架空デモ](../examples/fictional-revision/README.md)の採点差を効果実証に使ってはならない。

## 7. 比較形式の自動層別（事前検査）

[試験計画の判定器](STUDY_SELECTION_AND_EVIDENCE.md)を追加。歌詞本文だけ、他条件を固定した歌詞違いの音源、複数要素の異なる音源を別分類し、倫理・統制・事前計画の不足を検出する。実際の参加者データは未収集であり、分類器のPASSはリスナー効果の証明ではない。
